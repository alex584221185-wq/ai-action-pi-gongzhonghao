# 写作与视觉规则

先交代读者为什么关注这篇文章，再展开内容。活动预告可采用“读者问题—往期具体现场—本期讨论—适合谁—活动信息”，但不强制章节数或顺序。每期作者可保留自己的口吻。

把事实、推断和愿望区分开。“希望大家找到起点”是活动目标，不能写成“所有人都完成了产品”。已发生的活动需要回顾来源支持；仅有招募文章或主持计划时，只能确认计划、主题及照片可见的现场。

长段落优先拆为短段落；并列内容用清单，流程用编号，重要一句单独强调。不要每句换行或满屏加粗。一般在手机上每段 2—5 行，超过 6 行检查是否可以拆分。无法改动的引用或用户明确保留的文字可保留，并记录例外。

讲者身份按当期确认资料写。作者不是默认主理人，四人轮流执笔不改变团队共同运营的背景。是否邀请老成员、是否保留费用或二维码由当期需求决定。

## 图片

查看实际图片后再拟图注；描述可见场景，不从人物表情推断效果、评价或职业。记录人物身份是由用户确认、明确题注还是其他可靠资料提供。未知者写“参与者”等中性描述。

单张横图适合展示现场；保留原比例，避免将多人合影缩成很小的拼图。原图不改写；海报、二维码尤其要保持清晰与完整。脚本原样复制图片并核对哈希。需要压缩、替换、裁切时另存素材副本，不能把原文件直接覆盖。

每张图都在本期清单中标为“使用”或“未使用及原因”。正文用图片 ID 引用；图注放在配置中统一管理。缺图或用户要求使用的图片漏放时，构建必须失败，不静默省略。

## 墨绿色模板

| 项目 | 默认样式 |
| --- | --- |
| 主底 | #0F1410 |
| 首屏 | #1A271E |
| 卡片与图片区 | #1A2B23 |
| 强调 | #BDF42B |
| 正文 | #E7EDE7 |
| 图注与辅助信息 | #ADBBB1 |
| 正文 | 16px，1.9 倍行高，左对齐 |
| 首屏标题 | 30px，1.55 倍行高，按当期指定分行 |
| 手机内边距 | 正文 20px，首屏 24px |

分区用细线和留白；列表与引用提供阅读停顿。检查 360、390、430px 宽度，较长的标题可以调整断行或局部字号，不能为了固定两行缩成难读小字。

每期文件夹保留“来源与选图.md”：原文/PDF实际读取范围、事实依据、每张照片用途、当期特别要求及待确认项。来源记录不默认进入面向读者的正文或公开仓库。
